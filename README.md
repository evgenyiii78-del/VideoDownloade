# VideoDownloaderBot v0.6.0

## Яндекс Диск вместо сжатия (v0.6.0)

Файлы до `MAX_UPLOAD_MB` (по умолчанию 49 МиБ) отправляются в Telegram.
Более крупные файлы загружаются на Яндекс Диск, бот отправляет публичную ссылку
и кнопку скачивания. Кнопка «Уместить в 49 МБ» удалена; старые кнопки не запускают сжатие.
YouTube-видео и видео с русской дорожкой, превышающие лимит Telegram, сохраняются
без перекодирования, изменения разрешения и пропорций (обычно MKV).
Для небольших роликов остаётся подготовка совместимого с Telegram формата.
MP3 и субтитры также могут отправляться через Диск.

### Подключение на Bothost

1. Получите OAuth-токен своего Яндекс Диска с разрешениями на чтение и запись:
   [официальная документация API](https://yandex.com/dev/disk/rest/).
   Нужны права `cloud_api:disk.read` и `cloud_api:disk.write` для работы с обычной папкой.
2. В переменные окружения бота на Bothost добавьте:

   ```dotenv
   YANDEX_DISK_TOKEN=ваш_секретный_OAuth_токен
   YANDEX_DISK_FOLDER=VideoDownloaderBot
   MAX_DOWNLOAD_MB=512
   MAX_UPLOAD_MB=49
   ```

   Не отправляйте токен в чат и не коммитьте его в GitHub. Для бота желательно
   использовать отдельный аккаунт Диска. Имя папки — одно имя без `/`, `\` и `:`.
3. Обновите код из GitHub и перезапустите бота. Папка создаётся автоматически
   при первой загрузке. При пустом токене бот работает только в пределах лимита Telegram.
4. Проверьте ролик больше 49 МиБ: дождитесь сообщения о загрузке на Диск,
   откройте ссылку и скачайте файл. Затем проверьте маленький ролик и MP3.

`MAX_DOWNLOAD_MB` — отдельный лимит одного результата на сервере (по умолчанию 512 МиБ).
Он не повышает лимит Telegram. Для отдельных аудио/видеопотоков и сборки файла нужно
дополнительное временное место; на слабом хостинге задайте `MAX_CONCURRENT_DOWNLOADS=1`.
Загрузка на Диск выполняется по одной, потоково, без чтения всего файла в RAM.
При отключённом Диске лимит загрузки остаётся `MAX_UPLOAD_MB`.

Ссылки публичные: файл доступен любому, у кого есть ссылка. Публикуется только файл,
не вся папка. Имена уникальны; чужие файлы не перезаписываются и не удаляются.
Автоудаление на Диске **не включено**: контролируйте свободное место и удаляйте старые
файлы вручную (после удаления ссылка перестанет работать). При ошибке публикации файл
может остаться в папке Диска без ссылки. Локальные временные файлы удаляются после
завершения отправки, в том числе при ошибках.

Проверки API в тестах выполняются на имитации ответов. Для проверки реальной авторизации,
квоты и доступности API с Bothost необходим токен, заданный на хостинге.

Telegram-бот для скачивания доступных пользователю видео по ссылкам из Instagram, TikTok, YouTube и Pinterest.

## Новое в v0.4.0

- YouTube: обычные ролики, Shorts и ссылки `youtu.be`.
- Pinterest: фото и видеопины, в том числе короткие ссылки `pin.it`. Доски целиком не поддерживаются. Фотопины отправляются изображением, а при ограничениях Telegram — файлом.
- Выбор «Видео» / «MP3» (для Pinterest — «Фото / видео» / «MP3») после отправки ссылки. Кнопки работают 1 час и доступны отправителю ссылки.
- MP3 192 кбит/с отправляется как аудиофайл с названием. В ролике должен быть звук.
- Лимит размера применяется и к MP3. Для Instagram сначала загружается видео, поэтому оно тоже должно укладываться в лимит.

### Обновление на Bothost

Обновите код из GitHub, переустановите зависимости из `requirements.txt` и перезапустите бота.
При Docker-развёртывании пересоберите образ: он уже содержит FFmpeg и Node.js 22.
При обычном Python-развёртывании FFmpeg и Node.js устанавливаются с `requirements.txt`. Бот находит встроенные бинарники без `apt`, root и правки PATH. После обновления на Bothost обязательно запустите переустановку зависимостей / пересборку, затем перезапуск. Простого перезапуска старого окружения недостаточно.
Токен и настройки Instagram в `.env` сохраняются.

YouTube использует `yt-dlp[default]` и JavaScript runtime по [документации yt-dlp](https://github.com/yt-dlp/yt-dlp#dependencies).
Сайт может ограничивать загрузку с IP сервера; поддержку конкретной ссылки нужно проверять на хостинге.

## Если Instagram отвечает ошибкой

Instagram нередко требует авторизованную сессию даже для публичных Reels. Войдите в свой Instagram в браузере и возьмите значения cookies:

- `sessionid` — основное
- `csrftoken` — желательно
- `ds_user_id` — желательно

Добавьте только **значения** в серверный `.env`:

```env
INSTAGRAM_SESSIONID=ваше_значение_sessionid
INSTAGRAM_CSRFTOKEN=ваше_значение_csrftoken
INSTAGRAM_DS_USER_ID=ваше_значение_ds_user_id
```

После изменения:

```bash
docker compose down
docker compose up -d --build
docker compose logs -f bot
```

Бот сам создаёт временный Netscape cookie-файл при запуске. Реальные cookies нельзя коммитить в GitHub или отправлять в чат.

### Альтернативный способ

Можно использовать готовый Netscape-format `cookies.txt`:

```env
COOKIES_FILE=/app/secrets/cookies.txt
```

и раскомментировать соответствующий volume в `docker-compose.yml`.

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---:|---|
| `BOT_TOKEN` | — | токен Telegram-бота |
| `DOWNLOAD_DIR` | `downloads` | каталог временных файлов |
| `MAX_UPLOAD_MB` | `49` | максимальный размер отправляемого файла |
| `MAX_CONCURRENT_DOWNLOADS` | `3` | одновременно выполняемых скачиваний |
| `INSTAGRAM_SESSIONID` | пусто | cookie `sessionid` вашего Instagram |
| `INSTAGRAM_CSRFTOKEN` | пусто | cookie `csrftoken` |
| `INSTAGRAM_DS_USER_ID` | пусто | cookie `ds_user_id` |
| `COOKIES_FILE` | пусто | альтернативный путь к Netscape cookies |
| `FFMPEG_LOCATION` | пусто | путь к FFmpeg, если он не в `PATH` |


## Как работает Instagram в v0.4.0

1. Бот принимает обычную ссылку вида `https://www.instagram.com/reel/HASH/`.
2. Сначала пробует публичную загрузку без авторизации.
3. Если Instagram блокирует публичную загрузку, бот автоматически повторяет запрос через служебную Instagram-сессию, сохранённую на сервере.
4. Если служебная сессия тоже не сработала, используется best-effort публичный fallback.
5. MP4 отправляется пользователю в Telegram.

Пользователю не нужно входить в Instagram, передавать cookies или менять ссылку. Служебную сессию один раз настраивает администратор бота в переменных окружения Bothost.

## Исправление v0.4.1

Для Python-хостинга бинарники поставляются пакетами [imageio-ffmpeg](https://github.com/imageio/imageio-ffmpeg) и [nodejs-wheel-binaries](https://pypi.org/project/nodejs-wheel-binaries/). Системный FFmpeg и явный `FFMPEG_LOCATION` сохраняют приоритет. Встроенный Node.js передаётся yt-dlp по абсолютному пути.

## Исправление v0.4.2

Пропуск yt-dlp из-за MAX_UPLOAD_MB теперь распознаётся как превышение размера. Для YouTube бот повторяет загрузку в 480p, 360p и 240p, если выбранный вариант слишком большой. Если ни один не помещается, показывает лимит размера. Ошибка отсутствия файла больше не объясняется отсутствием FFmpeg.

## Исправление v0.4.3

Для YouTube приоритет H.264 + AAC. Перед отправкой проверяются настоящие видео- и аудиопотоки. Несовместимые кодеки конвертируются в H.264/yuv420p + AAC; совместимые копируются без перекодирования. MP4 получает faststart, размер проверяется после обработки.

## v0.5.0: готовые русские дорожки YouTube

Кнопка «Русская дорожка» скачивает видео только с доступным аудио, помеченным YouTube языком ru. Оригинальная иностранная дорожка вместо русской не подставляется. «Русские субтитры» отправляет отдельный VTT-файл: сначала авторские, затем автоматические русские. Автопереводы с tlang исключаются. Озвучка и перевод не генерируются, платный AI API не нужен. Если дорожек нет или они недоступны, бот сообщает об этом. Субтитры не вшиваются в кадр.


## Список пользователей

Бот сохраняет пользователей в SQLite-файл `downloads/users.sqlite3`. Каталог `downloads`
уже подключён как volume в Docker Compose, поэтому список сохраняется после перезапуска
и пересборки контейнера.

Чтобы включить админ-команду, добавьте в `.env` Telegram user ID администратора:

```env
ADMIN_ID=123456789
```

После перезапуска администратору доступна команда:

```text
/users
```

Она показывает до 100 последних пользователей: Telegram ID, username, имя,
количество отправленных ссылок и время последней активности. Команда недоступна
остальным пользователям.

## v0.5.1 — размеры YouTube

YouTube скачивается в лучшем доступном разрешении без лимита 720p и без понижения качества при превышении размера. Кнопка «Оригинал» возвращает потоки YouTube в файле без перекодирования (обычно MKV). Это доступная версия YouTube, не файл до загрузки автором. Обычная кнопка «Видео» сохраняет разрешение и готовит совместимые кодеки; размеры для Telegram читаются из готового файла с учётом DAR/поворота. Лимит MAX_UPLOAD_MB сохраняется: слишком большой файл не отправляется и не уменьшается.

## v0.5.2 — сжатие под лимит (история, отключено в v0.6.0)

Для YouTube добавлена отдельная кнопка «Уместить в 49 МБ» (число берётся из MAX_UPLOAD_MB). Двухпроходное кодирование H.264/AAC уменьшает битрейт без масштабирования или обрезки. Качество деталей может снизиться. «Видео» и «Оригинал» не уменьшаются автоматически. Входной файл ограничен 512 МБ (или MAX_UPLOAD_MB, если он больше), готовый файл проверяется по лимиту отправки. На обработку отведено до 15 минут. Очень длинный ролик может не поместиться.
